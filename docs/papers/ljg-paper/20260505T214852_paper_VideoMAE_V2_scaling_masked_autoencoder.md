# 问题

VideoMAE 在视频预训练上很有效，但扩展到十亿参数级别时遇到瓶颈——计算成本太高、内存消耗太大、数据量不够。

VideoMAE V2 就是来解决这些问题的：用双重掩码策略（编码器和解码器都掩码）降低计算成本，用渐进式训练策略（先在多源无标签数据上预训练，再在混合标签数据上后预训练）解决数据不足问题。

# 翻译

## 锚点：一个会偷懒的视频重建器

想象一个视频重建任务：给你一段视频，遮住 90% 的内容，让你重建被遮住的部分。VideoMAE 的做法是：编码器只看 10% 的内容，解码器重建全部 90%。

VideoMAE V2 更聪明：编码器只看 10%，解码器也只重建其中的一部分（比如 40%）。这样计算量降低了，但任务难度没变——因为解码器重建的那 40% 仍然是编码器没见过的。

## 双重掩码：编码器 + 解码器都掩码

```
VideoMAE（单重掩码）
├── 编码器：处理 10% 的可见 token
└── 解码器：重建全部 90% 的不可见 token
    -- 计算量大，内存占用高

VideoMAE V2（双重掩码）
├── 编码器：处理 10% 的可见 token
└── 解码器：只重建其中 40% 的 token
    -- 计算量降低 1/3，batch size 增加，训练时间减少
    -- 重建损失只计算编码器没见过的 token
```

**关键设计**：解码器用 running cell masking 选择要重建的 token，保证任务难度不变。

## 渐进式训练：多源数据 + 混合标签数据

```
第一阶段：多源无标签数据预训练
├── 混合多个视频数据集（Kinetics、Something-Something、AVA 等）
├── 数据多样性高，覆盖不同场景
└── 用 VideoMAE V2 自监督预训练

第二阶段：混合标签数据后预训练
├── 混合多个有标签数据集
├── 继续用 VideoMAE V2 预训练（不是微调）
└── 提升下游任务性能
```

## 效果

Kinetics-400：90.0% Top-1 准确率（SOTA）
Kinetics-600：89.9% Top-1 准确率（SOTA）
Something-Something V1：68.7% Top-1 准确率（SOTA）
Something-Something V2：77.0% Top-1 准确率（SOTA）

训练效率：ViT-g 模型在 64 个 A100 上训练时间从 2 周降到不到 2 周（双重掩码带来的提升）

# 核心概念

## 双重掩码策略

**一句话**：编码器和解码器都掩码，编码器只看 10% 的 token，解码器只重建其中 40% 的 token，降低计算成本但保持任务难度。

**为什么重要**：VideoMAE 的瓶颈在解码器——虽然编码器只处理 10% 的 token，但解码器要重建全部 90% 的 token，计算量仍然很大。双重掩码让解码器也只处理一部分 token，计算量降低 1/3，但重建任务的难度不变（因为解码器重建的仍然是编码器没见过的 token）。

## 渐进式训练范式

**一句话**：先在多源无标签数据上预训练（学通用特征），再在混合标签数据上后预训练（学任务相关特征），而不是直接在单一数据集上预训练。

**类比**：就像学英语，先读各种类型的文章（小说、新闻、科技）学通用语言能力，再专门读考试相关的文章学考试技巧。

**为什么重要**：视频数据集比图像数据集小得多（Kinetics-400 只有 0.24M 视频，ImageNet-22k 有 14.2M 图像）。单一数据集不够大，十亿参数模型容易过拟合。渐进式训练用多源数据增加数据多样性，缓解过拟合。

# 洞见

**视频预训练的瓶颈不在编码器，在解码器**——VideoMAE 用高掩码率（90%）让编码器只处理 10% 的 token，但解码器仍然要重建全部 90% 的 token。VideoMAE V2 的双重掩码证明：解码器也可以只重建一部分 token，任务难度不变，但计算成本大幅降低。这个洞见对所有掩码自编码器都有意义——不只是视频，图像、音频、文本的掩码自编码器都可以用双重掩码降低计算成本。

# 博导审稿

问题定位准确。VideoMAE 扩展到十亿参数时确实遇到计算和数据瓶颈。双重掩码和渐进式训练都是合理的解决方案。

实验扎实。在 Kinetics、Something-Something、AVA 等多个数据集上验证了有效性。消融实验覆盖了掩码率、解码器掩码策略、数据混合策略等多个方面。

但有一个根本性的问题：双重掩码的理论依据不够充分。论文说"解码器只重建一部分 token，任务难度不变"，但没有深入分析"为什么任务难度不变"。如果解码器重建的 token 数量减少，模型学到的特征会不会变差？论文只展示了下游任务性能没有明显下降，但没有分析学到的特征表示有什么变化。

另一个问题：渐进式训练的两个阶段都用 VideoMAE V2 预训练，但第二阶段用的是有标签数据。为什么不直接用监督学习，而是继续用自监督预训练？论文没有对比"第二阶段用监督学习"和"第二阶段用自监督预训练"的差异。

**判决：weak accept**。方法有效，实验结果好，但理论分析不够深入。作为工程论文可以接受，但需要补充理论分析。

# 启发

**迁移**：VideoMAE V2 的双重掩码策略可以迁移到其他掩码自编码器——图像的 MAE、音频的 AudioMAE、文本的 BERT。关键是让解码器也掩码，只重建一部分 token，降低计算成本。

**混搭**：VideoMAE V2 的渐进式训练 + ViTPose 的知识 token 迁移可以组合：第一阶段用大模型在多源数据上预训练，第二阶段用知识 token 把大模型的知识迁移到小模型，小模型在混合标签数据上后预训练。这比直接训练小模型更高效。

**反转**：VideoMAE V2 假设"解码器只重建一部分 token，任务难度不变"。但反过来想：如果解码器重建的 token 数量太少，模型可能学不到足够的特征。能不能设计一个"自适应掩码率"策略：训练早期解码器重建更多 token（学更多特征），训练后期解码器重建更少 token（降低计算成本）？
